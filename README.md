# OnePageIRC

A single page IRC client. Plain HTML, CSS, JavaScript and SVG — no frameworks,
no TypeScript, no build step, no third-party code. Copy the files onto any
static web host (or open `index.html` from disk) and it runs.

Generated by [AI Sloperator](https://www.aisloperator.com/) using Claude Code.

```
index.html            markup and the connect dialog
app.css               all styling, dark and light
app.js                protocol, UI, commands
icon.svg              favicon / app icon
manifest.webmanifest  lets iOS and Firefox install it to the home screen
```

## The one thing you must know about transport

**A web page cannot open a raw TCP socket.** No browser exposes one, so no
static page can talk to port 6667 the way a native client does. This client
speaks IRC over a **WebSocket**, which is the only socket a page is allowed to
open.

So the host and port you type must be an endpoint that accepts WebSocket
connections. Three ways to get one:

1. **A network that already runs a WebSocket listener.** Libera.Chat, for
   example, runs one for its own web client. Point the client at that host,
   port `443`, and tick *Secure WebSocket (wss://)* under Advanced.
2. **Enable WebSocket on your ircd.** ergo has it built in; InspIRCd has
   `m_websocket`; UnrealIRCd supports `websocket` in a listen block. Then any
   port you configure works directly.
3. **Run a gateway in front of an ordinary ircd** — kiwiirc's `webircgateway`
   is the usual one. Point this client at the gateway's host, port and path.

The connect dialog shows the exact WebSocket URL it will use as you type, so
you can check it before connecting.

Mixed content also applies: a page served over **https:** may only open
**wss:** connections. Serve the page over `http://`, open it as a `file://`
URL, or use a `wss://` endpoint.

## Connecting

On first load the client asks for:

| Field    | Default             |
|----------|---------------------|
| Server   | `irc.libera.chat`   |
| Port     | `6667`              |
| Nickname | `user` + 8 random digits |

Under **Advanced**: TLS (`wss://`), gateway path, WebSocket subprotocol
(some gateways want `text.ircv3.net`), real name, auto-join channels, server
password, and SASL PLAIN credentials.

Everything except the passwords is remembered in `localStorage`. Passwords are
never written to disk.

## Using it

- **Tabs** across the top: one for the server (system messages), one per
  channel, one per private conversation. Unread counts show on each tab; a red
  badge means you were mentioned. Swipe left/right in the message area on a
  touch screen to move between tabs.
- **User list** in each channel, sorted by rank then name. It is a fixed column
  on wide screens and a slide-over drawer on a phone — tap the people icon in
  the header. Tap a name to open a private tab.
- **Composer** at the bottom. Enter sends; Shift+Enter adds a line. Tab
  completes nicknames and commands, and a second Tab cycles the matches.
  Up/Down walk the input history.
- Nicknames get a stable colour, IRC formatting codes (bold, italic,
  underline, strikethrough, colour) are rendered, and URLs and `#channels`
  become links.

### Commands

`/help` lists them all. The common ones:

```
/join #channel [key]      /part [#channel] [reason]     /cycle
/msg target text          /query nick [text]            /me action
/notice target text       /nick newnick                 /topic [text]
/names                    /whois nick                   /who target
/list [pattern]           /invite nick [#channel]       /kick nick [reason]
/mode [target] modes      /op /deop /voice /devoice     /away [reason]
/ctcp target CMD          /ping [target]                /ns /cs /ms
/raw LINE                 /server [host [port]]         /disconnect
/quit [message]           /close                        /clear
/settings                 /help
```

Anything else after a `/` is uppercased and sent to the server as-is, so
`/lusers` or `/motd` work without being listed. To send a literal message that
starts with a slash, type two: `//not a command`.

## Protocol support

Message tags, `CAP LS 302` negotiation (`multi-prefix`, `server-time`,
`away-notify`, `account-notify`, `chghost`, `extended-join`,
`userhost-in-names`, `message-tags`, `invite-notify`), SASL PLAIN, ISUPPORT
(`PREFIX`, `CHANTYPES`, `CHANMODES`, `NETWORK`), NAMES/MODE tracking so the
user list stays correct, CTCP ACTION plus VERSION/PING/TIME/CLIENTINFO/SOURCE
replies, nickname-in-use retry, and PING/PONG keepalive.

One server connection at a time, by design.

## Browser support

Written against what Firefox and iOS Safari both ship: ES2017 syntax, no
optional chaining, CSS custom properties, flexbox and grid, `<dialog>` with a
fallback, and `visualViewport` so the iOS keyboard never covers the composer.
Safe-area insets are honoured, and the input uses a 16px font so iOS does not
zoom when it is focused.

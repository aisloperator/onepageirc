## What this is

**OnePageIRC** — a single page IRC client served as static files. The product
name is one word, no spaces; it appears in the page title, the header, the
manifest, the CTCP `VERSION` reply and the default real name. Hard constraints,
from the original brief — treat them as non-negotiable:

- No frameworks, no TypeScript, no third-party code, no build step, no package
  manager. `index.html` + `app.css` + `app.js` + `icon.svg` is the whole product.
- Only web standards that both Firefox and iOS Safari ship.
- One server connection at a time.

There is no build, no linter, no test suite, and no `package.json`. Do not add
one without being asked.

## Running and checking changes

```sh
python3 -m http.server 8000        # then open http://localhost:8000/
```

Serve over `http://` (or open `index.html` as a `file://` URL) rather than
`https://` — a page on https may only open `wss://` sockets, so plain `ws://`
testing needs a non-secure origin.

Verification is by loading it in a browser; there is nothing to run headlessly.
When no JS engine is available in the environment, check structure mechanically
(balanced braces/strings/regex literals in `app.js`, balanced CSS braces and
HTML tags) and review by reading.

## Transport reality

A browser cannot open a raw TCP socket, so this client speaks IRC over a
**WebSocket** (`wsUrl()` builds `ws(s)://host:port/path`). The host/port the
user types must be a WebSocket-capable endpoint — an ircd with WebSocket
enabled, or a gateway such as kiwiirc's `webircgateway`. The default port shown
in the dialog is 6667 because the brief asked for it, not because a bare 6667
ircd will answer. Do not "fix" this by pretending TCP is available.

## Architecture of app.js

One IIFE, no modules or exports, loaded by a plain non-deferred `<script>` at
the end of `<body>`. Sections in order: utilities → protocol parsing → `state`
→ `ui` element cache → tabs → chrome → message rendering → user list →
connection → `handlers` → `commands` → input → settings/dialog → boot.

**`state`** is the single mutable singleton (connection, settings, nick,
tabs, `isupport`, caps, input history). **`ui`** caches DOM references resolved
once at load.

**Tabs.** A tab record owns its own DOM: a `.log` scroller and a `.tab` button.
Every log is mounted at once, absolutely positioned, and switched with the
`hidden` attribute — that is what preserves per-tab scroll position, so don't
replace it with re-rendering. `state.byId` is keyed by `tabId(type, name)`,
which lowercases through `ircLower()` (rfc1459 casemapping: `[]\~` fold to
`{}|^`). **Any nick or channel used as a key must go through `ircLower`** —
`toLowerCase()` alone will desynchronise tabs and the user list.

**Inbound messages.** `handleLine` → `parseLine` (tags, prefix, params) →
`handlers[command]`. `handlers` is keyed by uppercased command name *or*
numeric-as-string (`'353'`). Unhandled three-digit numerics fall to
`numericFallback`; anything else is dumped raw into the system tab. Supporting
a new message means adding one key to `handlers`.

**Outbound commands.** `commands` is built by
`defc('name alias1 alias2', helpString, fn)`; the first name owns the help line
that `/help` prints, aliases get `help: null`. A slash command with no entry is
uppercased and sent to the server verbatim, so `/lusers` works unlisted.

**Rendering.** `print(tab, kind, who, body, opts)` → `formatBody()` (mIRC
bold/italic/underline/strike/colour codes) → `linkify()` (URLs and `#channel`
links). All output is built with `createElement`/`textContent`;
**never use `innerHTML` on anything derived from the network** — every string
from the server is untrusted. `opts.plain` skips formatting for text we
generated ourselves.

**ISUPPORT drives behaviour.** `state.isupport` (`PREFIX`, `CHANTYPES`,
`CHANMODES`) decides what counts as a channel (`isChannel`), how user-list
ranking sorts, and which mode letters consume an argument
(`modeTakesParam`/`applyChannelModes`). Defaults are set in `state` and
replaced by the 005 handler.

**Two state machines to be careful with:**

- *CAP negotiation.* `state.caps.negotiating` gates registration; every exit
  path — ACK, NAK, SASL success, SASL failure — must reach `CAP END`, or
  registration stalls forever with no visible error.
- *Auto-join.* `afterMotd()` is idempotent via `motdSeen` and fires on
  376/422, with a 4-second `setTimeout` backstop from 001 for servers that
  send no MOTD terminator.

## Layout and compatibility rules

- The composer stays above the iOS keyboard because `fitViewport()` writes
  `visualViewport.height` into the `--app-h` custom property, which sets
  `#app`'s height. Don't switch to `100vh`/`100dvh` alone.
- `#input` must keep a 16px font — anything smaller makes iOS Safari zoom the
  page on focus.
- In CSS, any selector that sets `display` needs a companion
  `selector[hidden] { display: none }` rule, since an author `display` beats
  the UA stylesheet's `[hidden]`.
- Nick colours are `hsl()` with **comma** syntax and `var(--nick-sat)` /
  `var(--nick-lum)` so they track the light/dark theme.
- Avoid syntax newer than the Firefox + iOS Safari floor: no optional
  chaining, no `??`, no regex lookbehind (a `SyntaxError` at parse time takes
  the whole file down on older iOS), no `.at()`, no `replaceAll`.
  `<dialog>.showModal()` and `scrollIntoView(options)` are used with fallbacks.
- Passwords (server password, SASL) are deliberately never written to
  `localStorage`; `saveSettings()` whitelists the fields it persists.
